### 初九 · 潜龙勿用：云原生开发基础

> *潜龙勿用，阳在下也。*
>
> 龙还潜伏在水底，不是不用，是时候未到。打好基础，方能厚积薄发。

**01 Linux基石：永远的底层语言**

- 文件系统与权限：一切操作的起点
- Shell三剑客：grep / sed / awk——小而美的文本处理哲学
- 进程与管道：Unix哲学的精髓
- 为什么AI时代依然要学Linux？因为所有AI框架最终都跑在Linux上

**02 容器化：新的"操作系统"**

- Docker基础：镜像、容器、Dockerfile
- 为什么容器是AI时代的标配？环境一致性、快速部署、资源隔离
- Dev Container：开发环境即代码，一键复现
- 一个数据科学家的Dockerfile长什么样？

**03 AI命令行：自然语言驱动的工作流**

- `llm` CLI：在终端里直接调用大模型
- 经典工具 + AI：用AI生成grep正则、sed脚本
- Shell脚本的AI化：自然语言描述 → 生成脚本 → 验证执行
- 但记住：先懂原理再用AI，否则你连AI生成的命令对不对都判断不了

**04 Git与AI协作：版本控制的新形态**

- Git依然是基石：commit / branch / merge / rebase
- AI辅助Commit Message：自动生成规范的提交信息
- AI代码审查：PR描述自动生成、代码风格检查
- Cursor / GitHub Copilot：AI结对编程的正确姿势

**05 云的基本素养：从"买服务器"到"租服务"**

- 三大云厂商概览：AWS / Azure / GCP
- 对象存储（S3 / OSS）：AI时代的"硬盘"
- Serverless函数：写一段代码就部署，不用管服务器
- 云GPU租赁：训练模型不用买显卡了

**06 Python环境管理的现代范式**

- `uv`：Rust写的包管理器，比pip快100倍
- `poetry` / `pdm`：依赖管理 + 虚拟环境一体化
- Conda并未消亡：数据科学环境的快速搭建
- 多环境管理：不同项目、不同Python版本、不同CUDA版本

> **初九心法**：潜龙的"潜"，不是躺平，是蓄力。2017年蓄力Linux，2026年蓄力"Linux + Docker + AI工具链"。基础打牢了，后面的龙才能飞起来。

### 九二 · 见龙在田：Python与AI编程范式

> *见龙在田，德施普也。*
>
> 龙出现在田野上，开始展现价值。掌握核心工具，就能在工作中快速产出。

**01 Python现代特性**

- 类型提示（Type Hints）：让AI更懂你的代码
- `match-case`：模式匹配，替代复杂的if-elif
- 异步编程（async/await）：AI应用的并发基础
- walrus运算符、f-string进阶、dataclass……
- 为什么这些特性在AI时代更重要？因为AI写的代码需要你能读懂和维护

**02 Vibe Coding：AI辅助编程的艺术**

- 什么是Vibe Coding？描述意图 → AI生成 → 调试调整
- Cursor / Copilot的高效使用技巧
- Prompt Engineering for Code：怎么问AI写代码
- 代码审查能力：AI写的代码，你要能看出问题
- 什么时候自己写，什么时候让AI写？——核心逻辑自己写，样板代码让AI写

**03 数据生态的新旧双雄**

- **NumPy**：永恒的数值计算基石
  - 数组运算的思维方式
  - 广播机制、索引切片、聚合统计
  - GPU加速：CuPy、JAX的numpy接口
- **Pandas**：数据处理的事实标准
  - DataFrame操作、分组聚合、合并连接
  - 什么时候Pandas不够用？
- **Polars**：Rust写的新一代DataFrame
  - 惰性求值与查询优化
  - 并行处理，速度是Pandas的5-10倍
  - 什么时候用Pandas，什么时候用Polars？

**04 SQL：不死的王者，反而更强**

- 为什么AI时代SQL更重要了？因为大模型也在学SQL
- 现代SQL语法：CTE、窗口函数、半连接
- 云数仓SQL：Snowflake / BigQuery / Databricks语法差异
- Text-to-SQL：自然语言转SQL的能力与局限
- 写出高效SQL的能力更值钱了——AI能写SQL，但写不出最优的SQL

**05 数据可视化的新范式**

- Matplotlib：论文级精细绘图的底线
- Plotly / Altair：交互式可视化，探索性分析首选
- **Streamlit**：几行代码构建数据App
  - 从分析到产品的最短路径
  - 快速原型验证：一天做出一个Demo
- AI辅助可视化：描述你想看什么，AI生成图表代码

**06 函数式编程的回归**

- 为什么AI时代函数式编程更重要？
  - Agent的组合本质是函数的组合
  - 纯函数更容易测试和调试
  - 不可变数据避免副作用
- Python中的函数式：map / filter / reduce / 管道
- 从"写步骤"到"组合函数"的思维转变

> **九二心法**：见龙在田，利见大人。这个"大人"，就是AI。Python依然是那条龙，但龙的装备升级了——从"自己写所有代码"变成"知道让AI写什么、怎么验证AI写的对不对"。

### 九三 · 终日乾乾：现代数据基础设施

> *君子终日乾乾，夕惕若厉，无咎。*
>
> 白天勤奋精进，夜晚警惕反思。这是最苦的阶段，也是打地基的阶段——数据基础设施，是AI的燃料库。

**01 湖仓一体：大数据的新范式**

- Hadoop的退位与湖仓一体的崛起
- 什么是Lakehouse？数据湖的灵活性 + 数据仓库的性能
- 三大表格式之战：Iceberg / Delta Lake / Hudi
- 从"先建模再存"到"先存了再说"的范式转变

**02 云数据仓库：数据分析的主战场**

- Snowflake / BigQuery / Redshift：按需付费、弹性伸缩
- 现代数仓设计：ELT而非ETL
- 物化视图、自动优化、查询缓存
- 数据建模思维依然重要：好的模型让查询快100倍
- `CREATE OR REPLACE`：现代SQL的开发模式

**03 向量数据库：AI时代的新HDFS**

- 为什么需要向量数据库？大模型的"长期记忆"问题
- 核心概念：
  - Embedding向量：把文字/图片变成数字
  - 相似度搜索：找到最像的那个
  - ANN索引：HNSW / IVF / PQ——为什么能快？
- 主流选型指南：
  - 原型阶段：Chroma / FAISS（零部署，本地文件）
  - 生产小团队：pgvector（不增加新组件）
  - 生产中大规模：Milvus / Weaviate（专用高性能）
  - 超大规模：Pinecone（全托管）
- 向量检索进阶：
  - 混合检索：关键词 + 向量，各取所长
  - 重排序（Rerank）：召回后再精排
  - 多模态向量：图文统一检索
  - 向量数据库的分布式部署与扩容

**04 流批一体：实时数据处理**

- 为什么需要实时？风控、推荐、监控——延迟敏感的场景
- **Apache Flink**：流处理的事实标准
- Spark Structured Streaming：微批处理的妥协
- 流批一体：同一套API处理批和流
- 但要警惕：不是所有数据都需要实时，很多场景T+1就够了

**05 语义层与上下文工程**

- 什么是语义层（Semantic Layer）？让机器读懂数据的含义
- 为什么AI需要语义层？大模型不懂你的业务指标
- 指标定义、维度关系、业务逻辑——结构化地喂给AI
- 上下文工程：为AI应用构建高质量的"知识底座"
- dbt / MetricFlow：现代数据栈中的语义层工具

**06 数据编排与质量**

- Airflow / Dagster / Prefect：数据管道的调度器
- 数据质量监控：Great Expectations / Soda
- 数据血缘：知道数据从哪来、到哪去
- 特征平台（Feast）：ML的基础设施，避免训练-服务偏差

> **九三心法**：终日乾乾，夕惕若。2017年的"乾乾"是Hadoop，2026年的"乾乾"是**湖仓一体 + 向量数据库**。大数据的核心矛盾变了：2017年是"存不下、算不动"，2026年是"怎么让大模型有记忆、有上下文"。向量数据库是AI时代的HDFS。

### 九四 · 或跃在渊：机器学习与MLOps

> *或跃在渊，进无咎也。*
>
> 龙在深渊中，或跃而上，或退而居。这是最关键的一跃——跃过去了，就是能驾驭模型的专家；跃不过去，就停在"调包侠"的阶段。

**01 传统机器学习的定位：AI时代的"手术刀"**

- 有了大模型，还需要学传统ML吗？——需要，而且更重要
- 分工论：
  - **大模型**：理解、生成、推理——"瑞士军刀"
  - **传统ML**：预测、分类、回归——"精准手术刀"
- 结构化数据预测：XGBoost / LightGBM依然是王者
- 小样本、高可靠性、可解释性要求高的场景：传统ML更可控
- 什么时候用大模型，什么时候用传统ML？——一张决策树帮你选

**02 AutoML：自动化的力量**

- H2O AutoML / PyCaret / FLAML：自动完成数据预处理、特征工程、模型调参
- AutoML能做什么、不能做什么
- 正确使用AutoML的姿势：快速基线 + 人工优化
- 特征工程的自动化：是解放还是陷阱？

**03 可解释AI（XAI）**

- 为什么需要可解释？信任、合规、调试
- 模型可解释性的层次：
  - 全局可解释：模型整体怎么工作的
  - 局部可解释：单个预测为什么是这个结果
- 常用方法：
  - SHAP：基于博弈论的特征重要性
  - LIME：局部可解释模型
  - 特征重要性、部分依赖图（PDP）
- 可解释性不是"玄学"，是AI产品化的必修课

**04 MLOps：从模型到系统的飞跃**

- 什么是MLOps？DevOps + ML = 让模型持续交付
- 模型生命周期管理：
  - 数据版本管理（DVC）
  - 模型版本管理（MLflow）
  - 实验追踪：记录每次训练的参数和结果
- 模型部署：
  - 批量推理 vs 实时推理
  - Triton / TorchServe：模型服务化
  - A/B测试：新模型上线前的验证
- 模型监控与漂移检测：
  - 数据漂移：输入数据分布变了
  - 概念漂移：数据和标签的关系变了
  - 怎么监控？什么时候需要重训练？
- Kubeflow：Kubernetes上的ML工作流

**05 深度学习基础：从感知机到Transformer**

- 神经网络的直觉理解：不是黑箱，是层级特征提取
- 反向传播：神经网络怎么"学习"的
- CNN：计算机视觉的基石
- RNN/LSTM：序列数据的传统方案
- Transformer架构的直觉：注意力机制为什么有效？
  - 不需要手动实现，但要懂原理
  - 理解了注意力，才能理解为什么大模型会幻觉
  - 理解了自回归，才能理解为什么上下文长度有限制

> **九四心法**：或跃在渊——这一跃，是从"会用工具"到"懂原理"的飞跃。2017年跃的是机器学习理论，2026年跃的是**MLOps + 大模型原理**。很多人在这里会迷茫：大模型黑箱、Prompt玄学、RAG坑多。坚定信念、扎实基础，才能跃过这道渊。

### 九五 · 飞龙在天：大模型与Agent应用

> *飞龙在天，大人造也。*
>
> 龙飞在天上，达到最高境界。这是全栈智能的集大成者——整合了前面所有的技术，构建端到端的智能系统。

**01 LLM基础：不必造轮子，但要懂原理**

- Tokenization：文字怎么变成数字
- Embedding：数字怎么变成向量
- Attention：模型怎么"关注"重要信息
- 自回归生成：一个字一个字往外蹦的原理
- 为什么大模型会幻觉？——概率性的本质
- 上下文窗口的限制与突破

**02 Prompt Engineering：新的编程范式**

- 这不是"写提示词"，是**用自然语言编程**
- 基础技巧：角色设定、少样本提示、格式约束
- 进阶技巧：
  - 思维链（CoT）：让模型"想清楚再回答"
  - 自洽性（Self-Consistency）：多次采样取多数
  - ReAct框架：推理 + 行动交替
  - 提示链（Prompt Chaining）：复杂任务拆解
- Prompt的工程化：版本管理、A/B测试、评估体系
- 核心原则：**Prompt不是玄学，是工程**

**03 RAG：检索增强生成**

- AI应用开发最核心的技术栈，没有之一
- 为什么需要RAG？
  - 知识有截止日期
  - 没有私有数据
  - 会幻觉
- RAG全流程详解：
  1. 文档加载：PDF / 网页 / 数据库 → 文本
  2. 文本切分：按什么策略切？（字符 / 语义 / 结构）
  3. 向量化：选什么Embedding模型？
  4. 索引构建：向量数据库怎么存？
  5. 检索：怎么召回最相关的文档？
  6. 重排序：召回后再精排
  7. 生成：上下文 + Prompt → 答案
- RAG进阶：
  - 多跳检索：一个问题需要多次检索
  - HyDE：先让大模型"猜"答案再检索
  - 查询改写：用户问题太模糊？先改写
  - 检索器路由：不同问题用不同数据源
- RAG评估：怎么判断RAG系统好不好？

**04 函数调用与工具使用**

- 大模型不只是聊天，还能做事
- Function Calling原理：大模型输出结构化的函数调用
- 工具使用模式：模型决定用什么工具 → 执行 → 返回结果 → 总结
- 这是Agent的技术基础
- MCP（Model Context Protocol）：AI时代的"USB接口"
  - 为什么需要MCP？统一工具调用协议
  - MCP Server：任何工具只要实现MCP就能被任何客户端使用
  - MCP生态：数据库、文件系统、浏览器、代码执行……

**05 Agent：AI应用的新范式**

- 什么是Agent？能自主规划、执行、反思的AI系统
- Agent的核心组件：
  - **规划（Planning）**：任务拆解、步骤生成
  - **记忆（Memory）**：短期记忆（对话历史）+ 长期记忆（向量库）+ 情景记忆
  - **工具使用（Tool Use）**：调用外部工具获取信息或执行动作
  - **反思（Reflection）**：自我评估、迭代优化
- 从"问答"到"做事"：AI的角色从"顾问"变成"执行者"

**06 Agent框架与多Agent协作**

- 主流框架对比：
  - **LangChain**：最流行、生态最全，但也最"重"
  - **LlamaIndex**：专注于RAG和数据连接
  - **AutoGen / CrewAI**：多Agent协作
  - **Semantic Kernel**：微软出品，企业级
- 框架陷阱警告：**先理解原理，再用框架**
- 多Agent协作模式：
  - 流水线模式：A做完传给B
  - 辩论模式：多个Agent互相辩论
  - 角色分工模式：产品经理 + 程序员 + 测试员
- 多Agent的挑战：协调成本、错误传播、Token消耗

**07 模型微调与部署**

- 先问：你真的需要微调吗？
  - 知识更新？→ 用RAG
  - 格式输出？→ 用Prompt Engineering
  - 风格模仿？→ 可以考虑微调
  - 领域适配？→ 小样本 + RAG先试试，不行再微调
- 微调技术谱系：
  - 全参数微调：最贵、效果最好、最容易过拟合
  - **LoRA / QLoRA**：只训练少量参数，性价比高
  - 前缀微调 / Prefix Tuning
- 开源模型生态：Llama 3 / Qwen / DeepSeek / Mistral
- 模型部署：vLLM / Ollama / TensorRT-LLM
- 量化技术：4-bit / 8-bit量化，消费级GPU也能跑大模型

**08 全栈AI应用架构**

- 一个完整的AI产品长什么样？
  - 前端：Next.js + React + Vercel AI SDK
  - 后端：FastAPI + Agent逻辑
  - 数据层：PostgreSQL + pgvector / 专用向量库
  - 模型层：大模型API + 微调模型 + Embedding模型
  - 监控层：日志、追踪、评估
- 从原型到生产：Demo很容易，生产化很难

> **九五心法**：飞龙在天——这是全栈智能的最高境界。2017年的"龙"是Spark，2026年的"龙"是**Agent**。为什么？因为Spark是大数据技术的集大成者，Agent是AI技术的集大成者——它整合了大模型、RAG、工具调用、记忆、规划。飞龙在天，利见大人——这个"大人"，是能驾驭AI的你。

### 上九 · 亢龙有悔：AI工程化与产品智慧

> *亢龙有悔，盈不可久也。*
>
> 龙飞得太高，会有悔恨。物极必反，飞到最高处才发现：技术不是全部，产品、成本、安全、伦理……这些"软技能"才是区分高手的关键。

**01 LLMOps：AI时代的运维**

- MLOps已经够复杂了，LLMOps更复杂
- 核心挑战：
  - 模型版本管理：Prompt版本、微调模型版本、RAG数据版本
  - 评估体系：怎么量化AI应用的好坏？
  - 监控：幻觉率、响应时间、Token成本、用户满意度
  - 安全：Prompt注入防护、数据泄露防护
  - A/B测试：新Prompt / 新模型上线前怎么验证？

**02 AI经济学：Token成本是生命线**

- 为什么成本意识在AI时代特别重要？
  - 一次RAG查询可能消耗几毛到几块钱
  - 规模上来了，Token成本就是天文数字
- 成本优化策略：
  - 模型分级：简单问题用小模型，复杂问题用大模型
  - 缓存策略：相似问题复用答案
  - Prompt压缩：减少不必要的上下文
  - 批量处理：能批量的不单独调用
- 自部署 vs API调用的成本对比
- 成本监控与预算控制

**03 AI产品思维**

- 技术人员最容易犯的错：拿着锤子找钉子
- 好的AI产品三标准：
  1. **真需求**：用户真的有这个痛点，不是你想象的
  2. **AI是最优解**：不是为了用AI而用AI
  3. **可持续**：成本可控、技术可维护、用户愿意付费
- 从"技术思维"到"产品思维"的转变
- AI产品指标体系：
  - 北极星指标：用户价值
  - 护栏指标：准确率、延迟、成本
  - 采纳率：用户用不用、爱不爱用

**04 什么时候不用AI**

- 这是最容易被忽略、也最重要的智慧
- 以下场景，AI可能不是最优解：
  - 精确计算：会计对账、数学证明 → 用传统程序
  - 高可靠性：医疗诊断、金融交易 → AI幻觉代价太大
  - 低延迟：实时风控 → 大模型推理太慢
  - 成本敏感：简单分类 → 规则引擎或传统ML便宜100倍
  - 数据极少：没有足够数据微调或做RAG
- **"能用AI解决所有问题"是新手的错觉，"知道什么时候不用AI"才是高手的智慧**

**05 AI伦理与安全**

- 数据隐私：训练数据和用户数据的边界
- 算法偏见：大模型会放大训练数据中的偏见
- Prompt注入：AI应用的新型安全漏洞
- 模型滥用：DeepFake、自动化攻击、虚假信息
- AI幻觉的应对：
  - RAG + 引用溯源
  - 交叉验证
  - 人工审核（关键场景）
- 合规要求：数据安全法、个人信息保护法、AI监管政策

**06 人机协作的新范式**

- AI不是替代人类，而是增强人类
- 怎么设计人机协作的工作流？
  - AI做初筛，人做终审
  - AI做体力活，人做决策
  - AI提供选项，人做选择
- 评估人机协作的效果：不是看AI多强，是看人机组合多强

> **上九心法**：亢龙有悔——飞到最高处，才发现还有更高的山。2017年的"悔"是反思技术，2026年的"悔"是**反思AI本身**。当你掌握了所有AI技术之后，最重要的智慧是知道AI的边界在哪里。"全栈"的终极不是"什么都会"，而是"知道什么该用、什么不该用"。

### 初六 · 履霜坚冰至：业务理解与问题定义

> *履霜，坚冰至。*
>

**01 第一性原理：从业务出发，而非从技术出发**

- 技术人员的通病：手里拿着锤子，看什么都是钉子
- 正确的姿势：先理解业务问题，再找合适的技术
- 怎么把模糊的业务问题转化为可执行的数据任务？
  - "用户流失很严重" → 定义流失 → 分析流失特征 → 建立预测模型 → 制定干预策略
- 5 Whys分析法：追问五次"为什么"，找到根本原因

**02 指标体系设计**

- 什么是好的指标？可衡量、可行动、可归因
- 北极星指标：一个最核心的指标，指引方向
- 护栏指标：不能为了北极星而牺牲的底线
- AI系统的指标体系：
  - 效果指标：准确率、召回率、用户满意度
  - 效率指标：响应时间、Token成本
  - 业务指标：转化率、留存率、收入
- 指标陷阱：虚荣指标 vs 可行动指标

**03 需求分析与优先级排序**

- 怎么判断一个AI需求靠不靠谱？
- RICE评分法：Reach / Impact / Confidence / Effort
- 技术可行性 vs 业务价值矩阵
- 快速验证：能用MVP验证的，就不要等完美方案
- 避免"伪需求"：用户说的不一定是他真正需要的

**04 行业知识的积累**

- 为什么行业知识很重要？数据是死的，不懂业务就读不懂数据
- 常见行业的数据特点：
  - 电商：用户行为、商品、交易
  - 金融：风控、反欺诈、信用评估
  - 安全：攻击检测、异常分析
  - 医疗：诊断辅助、影像识别
- 怎么快速积累行业知识？——读行业报告、跟业务同事聊天、做项目

> **初六心法**：履霜坚冰至——业务理解是坤卦的第一爻，也是最基础的。你对业务理解越深，数据就越有价值。否则，你就是个"只会跑模型的工具人"。

### 六三 · 含章可贞：数据驱动的决策文化

- 什么是数据素养？能读懂数据、用数据说话、用数据决策

  - 工具赋能：提供易用的数据工具，降低门槛

**02 A/B测试：科学决策的基石**

- 为什么需要A/B测试？因为"我觉得"不靠谱
- A/B测试的基本原理：对照组 vs 实验组
- 怎么设计一个好的A/B测试？

- 因果推断的方法：
  - 随机对照实验（A/B测试）
  - 倾向得分匹配（PSM）
  - 双重差分（DID）
  - 断点回归（RDD）
- 什么时候用什么方法？——一张决策图

**04 数据驱动的组织**

  - 从"取数的" → "赋能的"

  - 从"分析的" → "决策支持的"
- 怎么衡量数据团队的价值？——不是看做了多少报表，是看推动了多少业务决策

> **六三心法**：含章可贞——数据人的价值，不在于自己多厉害，而在于让整个组织变得更聪明。含章，就是把文采藏在里面，不张扬，但有力量。

- 数据投毒：污染训练数据

## 🔄 用九 · 群龙无首：技术选型的哲学

> *用九，见群龙无首，吉。*
>
> 看见所有的龙，却不知道哪条是首领——这才是最高境界。每个工具都有它擅长的领域，不要被任何一种技术绑架。

**01 大模型选型决策树**

- 闭源API（GPT-4o / Claude / Gemini）：效果最好、最省心、最贵
- 开源模型（Llama / Qwen / DeepSeek）：可控、可微调、需要算力
- 小模型（蒸馏/量化）：快、便宜、效果稍差
- 选型原则：先从API验证需求，有规模了再考虑自部署

**02 向量数据库选型指南**

- 原型阶段 → Chroma / FAISS
- 小团队生产 → pgvector
- 中大规模 → Milvus / Weaviate
- 超大规模 / 全托管 → Pinecone
- 核心原则：能不增加新组件就不加

**03 Agent框架选型**

- 简单RAG → 直接手写，不用框架（最可控）
- 复杂应用 → LangChain / LlamaIndex
- 多Agent → AutoGen / CrewAI
- 企业级 → Semantic Kernel
- 框架是工具，不是信仰——能用简单方案解决的，就别上复杂框架

**04 自建 vs 调用API**

- 调用API：快速、省心、按用量付费
- 自建：可控、定制化、长期成本可能更低
- 决策因素：数据敏感度、规模、定制化需求、团队能力

**05 什么时候用什么技术**

- 简单规则问题 → 规则引擎
- 结构化数据预测 → 传统ML（XGBoost/LightGBM）
- 文本理解与生成 → 大模型
- 知识问答 → RAG
- 复杂任务执行 → Agent
- 没有最好的技术，只有最合适的技术

> **用九心法**：群龙无首，吉。真正的高手，不是只会一种技术，而是知道每种技术的边界，在合适的场景用合适的工具。不要做"手里拿着锤子看什么都是钉子"的人。
