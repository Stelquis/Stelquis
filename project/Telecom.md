## 一、项目总览

### 1.1 项目背景

湖南电信与中南大学战略合作框架下的首批实习生入企项目，聚焦**移动网络用户感知大数据挖掘**。项目包含两条并行任务线：

| 任务 | 方向 | 一句话描述 |
| --- | --- | --- |
| 任务一 | 基站位置预测 | 从用户手机的无线测量报告（MR）中推断基站物理位置，支撑网元级质差定位 |
| 任务二 | 投诉意图识别 | 用微调分类模型替代不稳定的 Prompt，将用户投诉文本快速归类到五类标准故障场景 |

两条任务线的关系：任务一解决"基站在哪里"（网络侧），任务二解决"用户投诉的是什么"（客服侧）。两者共同服务于"用户感知质差挖掘"这一核心目标——发现网络问题（任务一）→ 理解用户诉求（任务二）→ 自动诊断路由（下游 Workflow）。

### 1.3 技术预备知识（面试高频概念）

> 本节整理项目涉及的核心概念与原理，方便面试时被追问能深入回答。

#### 1.3.1 坐标系与地图投影

**三种坐标系**：

| 坐标系 | 全称 | 通俗理解 | 使用场景 |
| --- | --- | --- | --- |
| WGS84 | World Geodetic System 1984 | GPS原始坐标，全球通用标准 | 工参表、国际地图 |
| GCJ02 | 国家测绘局02号标准 | "火星坐标"，中国对WGS84加偏加密（偏移100~700m不等） | 高德/腾讯地图、**MR数据** |
| BD09 | Baidu-09 | 百度在GCJ02基础上再加偏 | 百度地图、工参表（双套坐标） |

**为什么要统一**：GCJ02和WGS84对同一地点的经纬度差100~700m。如果用GCJ02的MR样点直接去跟WGS84的工参坐标做距离计算，会引入系统性偏差——所有样点都往同一个方向偏，算法再怎么优化也消除不了。本项目中，不转换时偏移P50=676m且方位角高度一致（方向一致性0.905），转换后偏移降至114m且方位角完全随机。

**Web Mercator投影（EPSG:3857）**：

- **问题**：经纬度是球面角度（单位：度），不能直接做加减、取中位数——因为经度1°在赤道是111km，在长沙（纬度28°）只有约98km，两个方向"一度"的实际距离不同
- **解决**：用Web Mercator投影把球面经纬度"摊平"成平面米制坐标（单位：米），所有聚合和距离计算在平面内进行，最后再转回经纬度
- **畸变修正**：投影会在高纬度产生面积拉伸，通过`cos(平均纬度)`因子修正。长沙（28°）的修正系数约1.135，修正后相对偏差<0.112%
- **通俗理解**：把橘子皮剥下来摊平——靠近两极的地方会被拉伸，需要修正

```
球面经纬度 ──→ Web Mercator平面（米制）──→ 聚合/距离计算 ──→ 转回经纬度
```

#### 1.3.2 无线信号概念

**MR（Measurement Report，测量报告）**：用户手机定期向基站上报的信号测量数据，包含用户位置（Lon/Lat）、关联小区ID、信号强度（RSRP）、信号质量（SINR/RSRQ）等。频率约每40ms~1s一次，是"用户在哪、信号好不好"的第一手数据。

**RSRP（Reference Signal Received Power，参考信号接收功率）**：
- 含义：手机接收到的基站参考信号功率，单位dBm（分贝毫瓦）
- 范围：-140 dBm（极弱）到 -44 dBm（极强），典型值-89 dBm
- 与距离的关系：理论上信号强度随距离增加而衰减（路径损耗模型），但实际受多径反射、建筑物遮挡、发射功率差异等影响，本项目中Spearman ρ仅-0.233（弱相关），不能单独用作"测距尺子"
- 通俗理解：RSRP像"声音大小"——离基站越远信号越弱，但墙壁、地形会让信号忽大忽小

**TA（Timing Advance，时间提前量）**：
- 含义：基站测量手机信号到达的时间差，换算为距离（LTE: 1 TA = 78m, 5G NR: 1 TA = 39m）
- 问题：本数据TA覆盖率仅0.11%，几乎不可用
- 量化误差：TA是整数值，天然存在±39m（5G）或±78m（LTE）的不确定性
- 通俗理解：TA像"回声测距"——基站喊一声，手机回一声，通过时间差算距离，但精度受限于"时间刻度"

**PCI（Physical Cell ID，物理小区标识）**：小区的"名字"，范围0~503（LTE）或0~1007（NR）。问题是PCI不够唯一——本数据中1008个PCI平均对应276个小区，无法通过PCI唯一定位到某个小区。

**EARFCN（E-UTRA Absolute Radio Frequency Channel Number）**：频点号，用于识别小区的工作频段（如1800M、2100M）。不同频段的信号传播特性不同，影响路径损耗模型参数。

**SINR（Signal to Interference plus Noise Ratio）**：信号与干扰加噪声的比值，反映信号质量。值越大越好，-9999表示脏数据。

#### 1.3.3 定位算法概念

**最小二乘法（Least Squares）**：
- 核心思想：给定多个"圆方程"（每个样点到基站的距离为半径画圆），求所有圆的最佳交点
- 数学形式：`X = (AᵀA)⁻¹AᵀB`，其中A是样点坐标矩阵，B是距离相关向量
- 问题：需要可靠的"圆半径"（样点到基站的距离），本项目缺少TA这根"尺子"，RSRP尺子又太弱，导致圆方程噪声被平方放大，Bootstrap取均值被少数大误差拖到200km外
- 通俗理解：三个圆交于一点就是基站位置——但如果圆的半径不准，交点会跑偏

**正则化（Regularization / Tikhonov）**：
- 问题：当样点分布不理想（如共线或近似共线）时，`(AᵀA)⁻¹`会接近奇异矩阵，解发散到天文数字
- 解决：在`AᵀA`的对角线上加一个小常数λ（如0.1），让矩阵变得"稳定"，代价是引入微小偏差
- 效果：B档中位半径从13,271m降至304m（↓97.7%）
- 通俗理解：像给摇晃的桌子垫个楔子——稍微歪一点，但不会再倒

**Bootstrap放回抽样**：
- 做法：从N个样点中随机抽4个（有放回），做一次最小二乘；重复1000次，取最优解
- 目的：减少单次抽样的随机性，通过大量重复找到最稳定的解
- 问题：如果每次抽样的距离噪声都很大，1000次平均仍然会被少数极端值拖偏
- 通俗理解：让1000个人分别猜一个数，去掉最高最低取平均——但如果每个人猜的依据都不靠谱，平均也没用

**DBSCAN（Density-Based Spatial Clustering of Applications with Noise）**：
- 核心思想：把空间上密集的点聚成一簇，稀疏的点标记为噪声
- 参数：eps（邻域半径，如200m）、min_samples（最少点数）
- 本项目中用途：多切片融合时，把不同切片对同一基站的预测结果聚类，取最大簇的中心
- 为什么最终不用：DBSCAN主簇与全样点中位数差<1m（噪声级），不引入额外复杂度

#### 1.3.4 NLP与微调概念

**StructBERT**：
- 全称：StructBERT Pre-training Language Model（达摩院）
- 本质：中文预训练语言模型，与BERT/RoBERTa同属Transformer Encoder架构
- 本项目使用：`damo/nlp_structbert_backbone_base_std`，约102M参数，21,128 token词表
- 通俗理解：一个"懂中文"的基础模型，已经学会了中文的语法和语义，但不知道"电信投诉"是什么——需要微调

**LoRA（Low-Rank Adaptation，低秩适配）**：
- 核心思想：不修改原始模型的全部参数（102M），而是在Transformer的注意力层旁边插入两个小矩阵A和B（秩r=8），只训练这299K参数
- 数学原理：原始权重矩阵W（d×d）的更新ΔW ≈ A×B，其中A是d×r，B是r×d，参数量从d²降到2×d×r
- 本项目配置：r=8, alpha=16, dropout=0.1, 目标模块=query和value注意力层
- 效果：可训练参数仅占总参数的0.29%（299K/102M），训练速度快，显存占用小
- 通俗理解：不重新教一个学生所有知识，只在关键知识点上做"补课"——高效且不容易忘记原有知识

**CrossEntropyLoss（交叉熵损失）**：
- 作用：衡量模型预测概率分布与真实标签之间的差距
- 公式：`L = -Σ yᵢ log(pᵢ)`，其中yᵢ是真实标签（one-hot），pᵢ是预测概率
- 类别权重：当类别不均衡时（如"无法上网"占50%、"无法收短彩信"仅2%），给少数类更高的权重，防止模型只学多数类
- 本项目：使用逆频率权重（如"通话质量差"权重4.052，"上网慢/卡"权重0.530），并设置上限20防止过度补偿
- 通俗理解：答错一道题扣分，少数类的题答错扣更多分

**TF-IDF（Term Frequency-Inverse Document Frequency）**：
- 作用：把文本转换为数值向量，衡量每个词对这篇文档的重要性
- 原理：TF（词频）× IDF（逆文档频率），一个词在当前文档出现多（TF高）且在其他文档出现少（IDF高），权重就大
- 本项目用途：字符级TF-IDF（2~5 gram）+ One-vs-Rest Logistic Regression 作为基线，成本极低（秒级），用于快速验证假设是否值得进入LoRA长训练
- 通俗理解：统计每个词的"稀缺程度"——"手机"出现很多但到处都有（不重要），"限速"出现少但只在这类投诉里（很重要）

#### 1.3.5 评估指标

**分类指标**：

| 指标 | 公式 | 含义 | 通俗理解 |
| --- | --- | --- | --- |
| Precision（精确率） | TP/(TP+FP) | 预测为某类的样本中，真正属于该类的比例 | "说对了多少" |
| Recall（召回率） | TP/(TP+FN) | 真正属于某类的样本中，被正确预测的比例 | "漏掉了多少" |
| F1 | 2×P×R/(P+R) | 精确率和召回率的调和平均 | "综合得分" |
| Macro-F1 | 各类F1的算术平均 | 每类等权，关注小类表现 | "小类也重要" |
| Micro-F1 | 全局TP/FP/FN计算 | 受大类主导 | "大类说了算" |
| Accuracy | 正确数/总数 | 整体准确率 | "答对了几道" |
| Exact Match | 完全匹配数/总数 | 多标签场景下完全预测正确的比例 | "全对才算对" |
| Hamming Loss | 错误标签数/总标签数 | 平均每个样本的标签错误数 | "错了几个标签" |

**为什么用Macro-F1而不是Accuracy**：本项目类别严重不均衡（"无法上网"占50%，"无法收短彩信"仅2%）。如果模型全判"无法上网"，Accuracy=50%，但"无法收短彩信"的F1=0。Macro-F1对每类等权平均，能暴露小类的问题。

**定位指标**：

| 指标 | 含义 | 通俗理解 |
| --- | --- | --- |
| P50（中位数） | 50%的基站误差低于此值 | "一半的站准到这个程度" |
| P90 | 90%的基站误差低于此值 | "九成的站准到这个程度" |
| 自洽性（Consistency） | 两份独立数据预测同一基站的结果差距 | "两次考试分数接近→答案可信" |
| 工参偏差 | 预测位置 vs 工参登记坐标的距离 | "离官方地址有多远"（非真值） |

**自洽性 vs 真实误差**：自洽性证明的是**稳定性**（两次预测一致），不是**准确性**（预测和真值一致）。如果算法稳定地偏向一个方向，自洽性会很好但偏差可能很大。本项目没有基站真值，所以自洽性是主指标，工参偏差仅作辅助参考。

## 二、任务一：基站位置预测

### 2.1 任务背景与业务价值

#### Situation（背景）

湖南电信需要做**网元级质差定位**——发现哪个基站/小区出了问题（设备故障、弱覆盖等），但基站位置数据往往不准或缺失。MR（测量报告）是用户手机定期上报的信号测量数据，包含用户位置、关联小区、信号强度等，是推断基站位置的天然数据源。

#### Task（任务）

基于MR数据和4G工参表，设计一种基站位置推断算法，预测每个基站（ENBID）的物理位置。

**核心约束**：
- TA（Timing Advance）覆盖率仅0.11%，不能用论文经典的"TA×78m→圆交会"方法
- 没有基站真实坐标作为真值，无法直接计算定位误差
- MR上报坐标是GCJ02（火星坐标），工参是WGS84，存在系统偏移

#### Action（行动）

1. **数据探索与预处理**：探索MR数据（100个分片，单片~198万行×44列）、45,546条工参记录，完成字段筛选、缺失率分析、4G/5G拆分、MR与工参关联（实际工作使用2个分片，关联后102,228行）
2. **坐标基准修复**：发现MR=GCJ02 vs 工参=WGS84的676m系统偏移，通过GCJ02→WGS84转换消除
3. **方案设计与验证**：设计4种预测策略（S1~S4），通过真实双分片自洽性验证稳定性
4. **多方案证伪**：系统性证伪了参数校准、邻区指纹、DBSCAN聚类、圆交会等6条技术路线
5. **工程收口**：合并5个脚本为单一管线`mr_pipeline.py`，统一坐标口径（WGS84 + Web Mercator）

#### Result（结果）

| 指标 | 数值 | 含义 |
| --- | --- | --- |
| 真实双分片自洽 P50 | **30.2m** | 两份独立数据预测同一基站，中位差距30米 |
| 工参偏差 P50 | **57.2m** | 预测位置 vs 工参登记坐标的中位差距 |
| 覆盖基站数 | 3,850站 | 2个分片（~3%数据）的预测覆盖 |
| 双分片验证站数 | 4,946站 | 两分片均有数据的基站 |

### 2.2 数据源与数据处理

#### 数据源

| 数据 | 路径 | 规模 | 作用 |
| --- | --- | --- | --- |
| MR数据 | `data/MR/MR-20260701/part-*.csv.gz` | 100分片，单片~198万行×44列（实际工作用2分片） | 用户测量样点（输入） |
| 4G工参表 | `data/MR/4G_CELL_20260728.tsv` | 45,546行×91列 | 小区配置与登记坐标（辅助参考） |
| MR关联表 | `data/MR/MR_4G.csv` | 102,228行×37列 | 2分片关联后的预测输入 |

#### 数据角色

```
MR数据的一行 = 某终端在某时间、某位置对关联小区的测量  → 观测样点（输入）
工参表的一行 = 一个4G小区的配置记录                    → 参考表（辅助）
预测目标 = 基站（ENBID）的物理位置                     → 输出
```

#### 关联关系


### 2.3 技术方案演进

#### 阶段1：Baseline——RSRP测距路线（7/7，失败）

**方案原理——路径损耗模型**：

无线信号随距离衰减的理论模型为：`RSRP = P_tx - 10·n·log₁₀(d) - c`，其中P_tx是发射功率，n是路径损耗指数（自由空间约2，城市约3~4），d是距离，c是常数（频率相关）。反推距离：`d = 10^((P_tx - RSRP - c) / (10n))`。

得到每个样点到基站的距离后，用最小二乘法求圆方程的交点，即基站位置。论文（paper.md）用TA×78m作圆半径，精度<200m（99%）。我们没有TA，改用RSRP反推距离。

**为什么失败**：

路径损耗模型的三个参数（P_tx/n/c）全为经验值。不同基站的发射功率不同（有的0dBm有的46dBm），城市环境的路径损耗指数差异大（高楼遮挡vs空旷地带），频率也不同。用一套经验值对所有基站做距离估算，误差被圆方程平方放大——B档（20~99条样点）的最小二乘解直接发散到13km。

**教训**：RSRP与距离的关系太弱（修正坐标后Spearman ρ也仅-0.233），不足以作为可靠的"测距尺子"。没有TA这根精确尺子，圆交会路线走不通。

#### 阶段2：正则化修复（7/13）

**方案原理——Tikhonov正则化**：

最小二乘法的核心是求解`X = (AᵀA)⁻¹AᵀB`。当样点分布不理想（如近似共线或数量不足）时，`AᵀA`接近奇异矩阵（行列式接近0），其逆矩阵的元素会非常大，导致解发散到天文数字。

Tikhonov正则化在`AᵀA`的对角线上加一个小常数λ：`(AᵀA + λI)⁻¹`。这保证了矩阵一定可逆，代价是引入微小偏差。λ越大解越稳定但偏差越大，λ越小越接近原始最小二乘但可能发散。

**效果**：λ=0.1时，B档中位半径从13,271m降至304m（↓97.7%），A档从374m降至228m（↓39%）。

**通俗理解**：像给摇晃的桌子垫个楔子——稍微歪一点，但不会再倒。

#### 阶段3：多切片融合（7/14）

**方案原理——逐切片定位+DBSCAN聚类**：

100个MR分片是按时间顺序切分的，每个分片包含不同时段的用户测量。对同一个基站，不同分片的样点来自不同用户、不同时间、不同位置——两次独立预测的结果应该接近（如果方法稳定的话）。

做法：每个分片独立做一次定位，得到该基站的一个预测位置；多个分片的结果用DBSCAN聚类，取最大簇的平均作为最终预测。DBSCAN的eps=200m，意味着预测点在200m以内算"同一簇"。

**为什么有效**：单切片可能受样点分布偏差影响（如某时段用户集中在某个方向），多切片融合能平均掉这种随机偏差。B档融合中位半径从单切片250m降至105m（↓58%），增益最大。

**为什么C档退化**：C档只有4~19条样点，各切片的预测位置本身就不稳定，散布>200m时DBSCAN每点自成簇，无法形成有效融合。解决方案：位置分散时放弃融合，退化为选残差最小的最佳单切片结果。

#### 阶段4：坐标基准修复（7/31，重大发现）

**问题发现过程**：

在讨论"样点中位数是否太简单"时，实测发现样点中位数vs工参锚点的位移P50=676m，且方位角高度一致（平均124°东南，方向一致性0.905，西/中/东分区几乎相同）。如果只是用户分布不均匀，方位角应该是随机的——高度一致说明是系统性偏移。

**验证方法——三假设排除法**：

| 假设 | 操作 | P50 | 方位角 | 判定 |
| --- | --- | --- | --- | --- |
| 基准（不转换） | 直接计算 | 676m | 高度一致（0.905） | 系统偏移 |
| MR=GCJ02→WGS84 | 转换MR坐标 | 114m | 完全随机（0.049） | ✅ 命中 |
| 工参BD09→WGS84 | 转换工参坐标 | 782m | 更差 | ❌ 排除 |

**判定依据**：只有坐标系对齐后，残差才会变成随机噪声。GCJ02→WGS84后方位角完全随机（平均单位矢量长度0.049，近乎0），这是"方向噪声消失"的充分条件。反向假设（工参BD09→WGS84）更差，排除。

**连锁影响**：坐标修正后，用户分布半径从692m降至187m，RSRP Spearman ρ从-0.101提升到-0.233，分箱单调性恢复（-130dBm→229m，-60dBm→108m）。此前所有"RSRP尺子失效、邻区指纹/DBSCAN全部证伪"的结论，部分根因是676m的系统偏移——样点内聚合无论怎么做都继承这个偏移。

#### 阶段5：方案定型——S4锚点折中（8/04）

**核心思想**：用户样点说"基站在A"，工参登记说"基站在B"，两个信息源都不完美但误差独立——"各信一半"（S4 = 0.5×A + 0.5×B）能同时压低两者的误差。

**数学直觉**：假设样点中位数的误差为σ₁，工参坐标的误差为σ₂，两者独立。则S4的误差方差 = (0.5)²σ₁² + (0.5)²σ₂² = 0.25(σ₁² + σ₂²)，而纯样点S1的误差方差 = σ₁²。只要σ₂ < √3·σ₁，S4就比S1好。

**实测验证**：

| 策略 | 做法 | 自洽P50 | 偏差P50 |
| --- | --- | --- | --- |
| S1 | 纯样点中位数 | 60.2m | 114.4m |
| S2 | GPS_high样点中位数 | 85.6m | 145.5m |
| S3 | RSRP加权质心 | 88.2m | 133.9m |
| **S4** | **0.5×S1 + 0.5×工参** | **30.2m** | **57.2m** |

S4在全部3,850个基站上没有一站比S1更差（改善幅度正好是50%，与α=0.5的数学关系完全吻合）。

**为什么固定α=0.5，不用动态α**：

试过α=min(1,n/20)的自适应方案——样点充足（≥20条）时完全信MR（α=1），样点稀少时靠工参锚点稳住（α<1）。理论上合理，但实测发现：同一基站两个分片的样点数不同（如分片A有8条→α=0.4，分片B有15条→α=0.75），折中比例不一致，两次预测被拉到不同位置，直接毁掉自洽性。自适应方案总体自洽P50=73.4m，远差于固定α=0.5的30.2m。

**为什么中位数不是"太简单"**：

修正坐标后实测6种聚合方式：

| 聚合 | α=1自洽 | α=1偏差 | α=0.5自洽 | α=0.5偏差 |
| --- | --- | --- | --- | --- |
| 中位数 | 60.5m | 122.6m | 30.2m | 61.3m |
| MAD裁剪 | 60.2m | 124.5m | 30.1m | 62.2m |
| GPS_high | 85.6m | 139.4m | 42.8m | 69.7m |
| RSRP加权 | 88.2m | 135.2m | 44.1m | 67.6m |

中位数全面优于GPS_high、RSRP加权、组合。MAD裁剪与中位数持平（差<1m）。奥卡姆剃刀：简单即最优，不引入复杂度。

**为什么RSRP加权不如中位数**：RSRP与距离的相关性太弱（ρ=-0.233），用RSRP加权相当于给一个噪声信号赋予了权重，反而引入了额外误差。在信号-距离关系不可靠的情况下，等权中位数比"加了噪声权重的质心"更稳健。

### 2.4 关键决策与踩坑记录

#### 已证伪的技术路线

| 路线 | 证伪原因 | 教训 |
| --- | --- | --- |
| RSRP→路径损耗→距离→最小二乘 | 参数无真值校准，B档发散到13km | 没有TA"尺子"，此路不通 |

### 3.3 模型方案与迭代历程

#### 模型架构

| 组件 | 选型 |
| --- | --- |
| 基座 | `damo/nlp_structbert_backbone_base_std`（达摩院中文StructBERT，~102M参数） |
| 微调 | LoRA（r=8, alpha=16, dropout=0.1, target_modules=["query", "value"]） |
| 输出 | 5类单标签（softmax + 加权CrossEntropyLoss） |
| 可训练参数 | ~299K（占基座0.29%） |
| 最大文本长度 | 128 token |
| 训练配置 | batch=32, lr=1e-4, 最多12 epoch, 早停patience=3 |

#### 为什么选StructBERT + LoRA

**为什么不用大语言模型（LLM）直接做分类**：
- LLM（如DeepSeek/Qwen）是生成模型，推理延迟1~3秒/条，不适合实时路由场景
- LLM的Prompt分类结果不稳定——同一条投诉换种问法可能给出不同分类
- 分类任务不需要"生成能力"，用编码器（Encoder）做判别更高效

**为什么选StructBERT而不是BERT/RoBERTa**：
- StructBERT是达摩院专门为中文优化的预训练模型，在中文NLU任务上表现优于原版BERT
- 魔塔社区原生支持，内网下载秒下，无网络依赖
- 参数量适中（102M），LoRA微调后可训练参数仅299K，CPU训练也可接受

**LoRA的原理与优势**：
- 全参数微调：更新102M参数，显存占用大，容易过拟合（小数据集上）
- LoRA：冻结原始权重W，在注意力层的query/value旁边插入两个小矩阵A（d×r）和B（r×d），只训练A和B
- 数学关系：`W' = W + ΔW = W + A×B`，其中r=8远小于d=768，参数量从d²=589K降到2×d×r=12K（每层）
- 效果：可训练参数仅占0.29%，训练速度快（CPU约25分钟），推理时Adapter权重仅1.2MB

**LoRA超参数选择**：
- `r=8`：低秩近似的秩，越大表达能力越强但参数越多。r=8在小数据集上足够
- `alpha=16`：缩放因子，控制LoRA更新的幅度。alpha/r=2是常用比例
- `dropout=0.1`：LoRA层的正则化，防止过拟合
- `target_modules=["query", "value"]`：只在注意力的query和value矩阵上加LoRA，不碰key和output——因为query和value负责"关注什么"，对分类任务最关键

#### 训练策略详解

**类别权重（Class Weight）**：

五类标签严重不均衡（"无法上网"占50%，"无法收短彩信"仅2%）。如果不用类别权重，模型会倾向于全判大类——因为这样Loss最低。

解决方案：使用逆频率权重，`w_i = (总样本数 / 该类样本数)^power`，并设置上限20（后调整为10）。power=1.0是线性逆频率，power<1会压缩权重差异。

本项目最终权重：无法上网0.674、上网慢/卡0.530、无法主被叫1.113、通话质量差4.052、无法收短彩信2.062。"通话质量差"权重最高（4.052），因为它样本最少但业务重要性不低。

**早停（Early Stopping）**：

验证集Macro-F1连续3个epoch不提升就停止训练，防止过拟合。本项目中v11在epoch 7达到最佳验证Macro-F1，epoch 10早停并恢复最佳权重。

**学习率（Learning Rate）**：

lr=1e-4是LoRA微调的常用值。全参数微调通常用2e-5（更小，因为要更新的参数更多）。学习率太大会导致训练不稳定，太小会收敛慢。

**动态Padding**：

不同文本长度不同（如"没网了"只有3个token，"手机最近上网特别慢有时候直接上不去"有15个token）。动态Padding以batch内最长文本为准做Padding，比固定128长度节省计算量。

#### 集成学习（Ensemble）

**原理**：训练3个相同架构的模型，只改变随机种子（42/43/44），推理时对每个类别的概率取平均，再做argmax。

**为什么有效**：不同种子的模型会学到略有不同的特征表示，集成能平均掉单模型的随机误差。本项目中单模型Macro-F1为0.888~0.890，集成后达0.8909，Oracle上界0.9038（如果每次都选对的话）。

**分歧率（Disagreement Rate）**：三模型预测不一致的样本占比4.81%。这些样本是"边界案例"——模型不确定的，正是需要人工复核的。

#### 争议数据复核闭环

**流程**：
```
三模型集成 → 分歧样本提取 → build_review_queue.py
→ LLM预批注（DeepSeek V4 Flash）→ 人工复查（只填review_decision和reviewed_label）
→ apply_review_to_test.py 写回test.csv
```

**三种决策**：
- `in_scope`：更新正式测试标签（如原来标"无法上网"，确认应为"上网慢/卡"）
- `out_of_scope`：从测试集移除（如"查套餐是否限流"不属于五类故障）
- `ambiguous`：从测试集移除（如"通话有问题"无法确定是无法主被叫还是通话质量差）

**为什么不让LLM直接标注**：LLM的预批注只是辅助，不能替代人工判断。因为标签边界涉及业务定义（如"无法主被叫"vs"通话质量差"的区分标准），需要领域专家确认。

### 3.4 关键决策与踩坑记录

#### 最关键的踩坑：词表Bug

**现象**：v1~v5的Macro-F1都在0.14左右，模型只预测前两类。

**诊断链**：
1. 100条强制过拟合50 epoch → Accuracy 0.20，全部预测为"无法收短彩信" → 记忆训练样本也失败
2. tokenizer只读校验 → 原仓库`vocab.txt`只有**5个token**（[PAD], [UNK], [CLS], [SEP], [MASK]）
3. 训练集未知词比例**1.0** → 所有中文文本都被编码为[UNK]
4. 上传完整词表后再次过拟合 → 词表文件SHA和21,128行均正确，但tokenizer仍解析为5 token
5. 定位到Transformers 5.8.1的API变更：`vocab_file=`改为`vocab=`

**修复**：引入标准`bert-base-chinese`完整词表（21,128 token），脚本按安装版本自动兼容两种参数。修复后100条过拟合Accuracy/Macro-F1均为1.0，v11真实全量训练Macro-F1达0.8135。

**教训**：当模型表现异常时，先验证输入是否正确，而不是调参。

## 四、方法论与工程原则

### 4.1 迭代方法论

两条任务线共用一套迭代方法论，核心原则：

**1. 每轮只验证一个假设**

不叠加多种改动，确保因果可追溯。例如：意图识别第8轮只做"通话质量差过采样"，第9轮只做"标签边界清洗"，第10轮只做"降低pos_weight上限"。

**为什么必须这样做**：如果同时改了数据、改了模型、改了超参数，效果提升了——你不知道是哪个改动起了作用，也无法复现这个改进。这是科学实验的基本原则：控制变量法。

**反面教训**：意图识别V3同时用了DeepSeek数据增强+新测试集+新训练配置，测试100%准确率——后来发现是训练/测试数据泄漏导致的假象。如果每轮只改一个变量，泄漏会更早被发现。

**2. 先低成本门槛，再长训练**

意图识别每轮先用TF-IDF + Logistic Regression基线做快速验证（秒级），通过后再进入StructBERT + LoRA长训练（分钟~小时级）。避免在无效假设上浪费长训练时间。

**TF-IDF基线的逻辑**：如果一个假设在简单模型上都没有改善（如TF-IDF + LR），那在复杂模型上改善的概率也很低。先用秒级实验排除明显无效的方向，再投入小时级的长训练。

**实例**：第四轮"泛化语音投诉补双标签"，TF-IDF基线结果为Macro-F1 0.428，明显弱于第三轮的0.442——直接否决，没有进入LoRA长训练，节省了约2小时。

**3. 固定测试集，不触碰**

- 测试集哈希校验（SHA-256），任何修改都能被检测
- 不根据测试Badcase临时造规则——否则测试集就变成了"为模型定制的答案"
- 不把测试集样本复制进训练集——否则测试集失去独立性
- 测试集只用于最终评估，不参与模型选择——模型选择用验证集

**为什么验证集和测试集要分开**：验证集用于早停和选最佳checkpoint（模型选择），测试集用于最终评估（泛化能力）。如果用同一份数据既选模型又评估，会高估泛化能力——就像用考试题做练习题，分数不代表真实水平。

**实例**：意图识别验证集Macro-F1接近0.999，但独立测试集只有0.8909。如果用验证集选模型，会误以为模型已经接近完美。

**4. 奥卡姆剃刀：简单即最优**

**原理**：当多个方案都能解释现象或解决问题时，选择假设最少、最简单的那个。不是"越复杂越好"，而是"在数据支撑范围内选最简方案"。

**在本项目中的应用**：

| 场景 | 复杂方案 | 简单方案 | 实测结果 | 选择 |
| --- | --- | --- | --- | --- |
| 样点聚合 | RSRP加权质心、GPS筛选、DBSCAN聚类 | 中位数 | 中位数全面最优 | 简单 |
| 锚点折中 | 自适应α=min(1,n/20) | 固定α=0.5 | 固定更稳定（30m vs 73m） | 简单 |
| 模型选择 | 更大模型、更多层LoRA | StructBERT + LoRA r=8 | 299K参数已足够 | 简单 |
| 数据增强 | DeepSeek生成、规则替换 | 用原始生产数据 | 原始数据更可靠 | 简单 |

**为什么简单方案往往更好**：
- 复杂方案引入更多参数/假设，每个参数都可能出错
- 小数据集上复杂方案容易过拟合——学到数据的噪声而非信号
- 复杂方案的可解释性差，出问题时难以定位根因

**5. 第一性原理：只关心最终目标**

**原理**：回到问题的最基本事实，从零开始推理，而不是被现有的解决方案或"常识"束缚。

**在本项目中的应用**：

| 现有"常识" | 第一性原理思考 | 结论 |
| --- | --- | --- |
| "RSRP可以测距" | RSRP与距离的相关性有多强？实测ρ=-0.233 | 不够强，放弃 |
| "邻区指纹可以定位" | PCI+EARFCN能唯一标识小区吗？不能，平均13.6个/键 | 放弃 |
| "DBSCAN聚类更合理" | 与简单中位数差多少？<1m | 不值得引入复杂度 |
| "自适应α更智能" | 自洽性真的更好吗？30m vs 73m | 反而更差 |
| "更大模型效果更好" | 当前瓶颈是模型容量还是数据质量？数据标签 | 不换模型 |

**第一性原理 vs 类比推理**：
- 类比推理："别人用RSRP测距效果好，我也用"——但别人的数据可能TA覆盖率高、坐标系统一
- 第一性原理："我的数据TA覆盖率0.11%、坐标系混用，RSRP测距还有效吗？"——从数据本身出发

**6. 可复现闭环**

```
Run → Commit → Tag → Log
运行 → 提交 → 打标签 → 记录结论
```

每轮实验保留：Adapter权重、阈值文件、训练元数据、Badcase文件、输入数据SHA-256。

**为什么需要SHA-256**：确保输入数据没有被意外修改。如果下一轮结果异常，先检查数据SHA是否变化——排除"数据被人动过"的可能性。

**为什么保留Badcase**：Badcase是"模型犯了什么错"的直接证据。下一轮优化时，先看Badcase有没有改善，再看总分——总分可能掩盖了个别类别的退化。

### 4.2 根因分析方法

两个任务都经历了"多轮失败→根因定位→关键修复→效果飞跃"的过程。根因分析的核心方法论是**排除法**——逐步排除假设，直到找到真正的瓶颈。

#### 根因分析五步法

```
Step 1: 从结果异常出发（精度太差/模型塌缩/指标不升反降）
Step 2: 列出所有可能的假设（参数？模型？数据？输入？评估？）
Step 3: 用最小可复现实验逐一验证
Step 4: 找到根因后一次性修复
Step 5: 验证修复效果，确认因果关系
```

#### 任务一的根因链

```
B档半径13km发散
  → 排查：路径损耗参数（P_tx/n/c）全为经验值
  → 验证：消除发射功率差异后ρ仍仅-0.067
  → 结论：RSRP与距离的关系太弱，不是参数问题而是"尺子"本身不可靠
  → 转向：放弃RSRP测距，改用样点中位数+锚点折中

样点中位数偏移676m
  → 排查：GPS误差？用户分布不均？坐标系问题？
  → 验证：方位角高度一致（方向一致性0.905）→ 系统偏移，不是随机分布
  → 假设检验：GCJ02→WGS84后偏移降至114m、方位角完全随机 → 命中
  → 结论：MR=GCJ02 vs 工参=WGS84，坐标系混用是最大系统误差源
```

#### 任务二的根因链

```
v1~v5 Macro-F1都在0.14
  → 排查：学习率？模型容量？类别权重？训练循环？
  → v5全参数微调，损失1.611≈ln(5) → 训练未获得有效监督信号
  → v6强制100条过拟合，Accuracy 0.20 → 即使记忆样本也失败 → 问题在输入
  → v7 tokenizer校验 → vocab.txt只有5个token → 所有中文→[UNK]
  → 修复：上传完整词表 → v10过拟合验证1.0 → v11全量训练0.8135
```

#### 关键诊断技巧

**1. 强制过拟合测试**：用极小数据集（如100条）训练极多epoch（50轮），如果模型连训练数据都记不住，说明输入或训练链路有问题。

**2. 方位角分析**：如果误差的方位角高度一致（方向一致性>0.9），说明是系统性偏移而非随机误差——需要排查坐标系、投影等全局问题。

**3. 分档分析**：按样点数量分档（如2~5条、5~10条、≥20条）看指标变化——如果样点越多越稳，说明方法本身是可靠的，瓶颈在数据量；如果样点多少都没区别，说明方法本身有问题。

**4. 交叉验证**：用两份独立数据分别预测同一目标，如果结果一致，说明方法稳定；如果不一致，说明方法对数据分布敏感。

## 五、简历亮点提炼

> 以下是可直接用于简历的成果描述，按STAR结构组织。

### 亮点一：基站位置预测

**基于MR数据的基站位置推断算法**

- 面对TA（Timing Advance）数据覆盖率仅0.11%的约束，放弃传统TA测距路线，设计了"样点中位数 + 工参锚点折中"的预测策略（S4，固定α=0.5）
- 发现MR上报坐标为GCJ02（火星坐标）而工参为WGS84的坐标系混用问题，通过数据反推验证（676m系统偏移→转换后114m→方位角残差随机），消除最大系统误差源
- 在无基站真值的条件下，设计"真实双分片自洽性"评估方案：将数据切成两个独立分片各自预测，以两次结果的一致性证明方法稳定性
- 系统性证伪了参数校准、邻区指纹、DBSCAN聚类、圆交会等6条技术路线，最终方案在3,850个基站上实现：双分片自洽P50=30.2m，工参偏差P50=57.2m
- 合并5个独立脚本为单一管线`mr_pipeline.py`，实现从坐标自检到预测到验证的全流程自动化

### 亮点二：投诉意图识别

**基于StructBERT+LoRA的电信投诉意图分类模型**

- 从48万条电信客服工单中提取用户真实投诉描述（44%无备注工单直接丢弃，剩余工单需从系统元数据包围中提取用户语句），构建27,614条训练集和499条独立测试集
- 基于StructBERT Base（~102M参数）+ LoRA（299K可训练参数，占0.29%）的轻量级微调方案，实现五类投诉意图单标签分类
- 经历15+轮迭代优化，关键根因修复：发现ModelScope仓库词表文件损坏（仅5个token），导致所有中文文本被编码为[UNK]，修复后Macro-F1从0.14跃升至0.81
- 设计三种子等权集成方案，独立测试集Macro-F1达0.8909，Exact Match达0.8898
- 建立完整的争议数据复核闭环：三模型分歧样本→LLM预批注→人工复查→写回测试集，确保测试集质量

### 亮点三：方法论与工程能力

**数据驱动的迭代优化方法论**

- 遵循"每轮只验证一个假设"的迭代原则，先用低成本基线（TF-IDF）做门槛验证，再进入长训练（LoRA），避免在无效假设上浪费计算资源
- 固定测试集哈希校验，不根据测试Badcase临时造规则，确保评估的独立性和可比性
- 运用第一性原理和奥卡姆剃刀：实测6种聚合方式后选择最简单的中位数，系统性证伪6条"更高级"的技术路线
- 建立可复现实验闭环：每轮保留Adapter权重、阈值、训练元数据、Badcase文件和输入数据SHA-256
